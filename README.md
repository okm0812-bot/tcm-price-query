# 科學中藥各廠價格查詢系統

輸入藥品名稱，即可比較各藥廠牌價，並支援折扣與 5+1 / 10+1 買贈換算。

## 線上版

- GitHub Pages：<https://okm0812-bot.github.io/tcm-price-query/>
- Repo：<https://github.com/okm0812-bot/tcm-price-query>

**Git repo 是唯一來源**：改動請改 repo 內的 `index.html` 再推上去，Pages 會自動重建。

上線後若 Google 試算表仍未公開，頁面會退回 `sample-data.csv`，再退回程式內建的示範資料
（狀態列以紅字標示非實際牌價）。
要讓線上版顯示真實資料，把匯出的 CSV 改名為 `data.csv` 一起 commit 推上去即可。

## 檔案說明

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 主程式（單檔，含樣式與邏輯，可直接部署） |

## 使用方式

### 本機測試（建議）

雙擊 `start.bat`，會開啟 `http://localhost:8123/`。

> 直接用 `file://` 開啟 index.html 時，瀏覽器會基於安全限制阻擋讀取本地 CSV，
> 此時請改用「載入本機 CSV」按鈕手動選檔，或使用 `start.bat`。

### 線上部署（GitHub Pages）

1. 把 `index.html`（可一併放入 `data.csv`）上傳到 GitHub repo
2. repo → Settings → Pages → Source 選 `Deploy from a branch`，分支 `main`、路徑 `/ (root)`
3. 取得 `https://<帳號>.github.io/<repo>/` 連結

> 部署到 Pages 後，資料會優先抓 Google 試算表；若試算表仍未公開，會退回同目錄的 `data.csv`，
> 再退回 `sample-data.csv`，狀態列會標明目前用的是哪一個來源。

## 資料來源與載入順序

程式依序嘗試，成功即停止：

1. **Google 試算表 CSV** — `CSV_URL`（`index.html` 內常數）
   - 試算表權限必須設為「任何人有連結即可檢視」
   - 工作表需為第一張（`gid=0`）
2. **本地 `data.csv`** — 把試算表「檔案 → 下載 → 逗號分隔值(.csv)」後，放進同一資料夾並改名
3. **`sample-data.csv`** — 示範資料，狀態列會以紅字標示「非實際牌價」
4. 三者都失敗時，畫面顯示操作提示，可用「載入本機 CSV」直接選檔

### 表頭格式

```
分類,品名規格,富田,仙豐,順天堂,科達,莊松榮,勝昌,港香蘭,天明,天一,萬國,國科
```

- 「分類」與「品名規格」欄名可用別名（類別/品類；品名/品項）
- 表頭若不在第一列（上方有標題列），程式會自動往下找
- 缺少某藥廠欄位時，狀態列會用紅字列出缺少的欄位名稱

## 計算規則

| 模式 | 公式 | 範例（原價 1000） |
| --- | --- | --- |
| 原價 | 原價 × 折扣 | 10 折 → 1000 |
| 5+1 | 原價 × 折扣 × 5/6 | 10 折 → 833 |
| 10+1 | 原價 × 折扣 × 10/11 | 10 折 → 909 |
| 6 折 + 5+1 | 1000 × 0.6 × 5/6 | 500 |

- 先套折扣、再套買贈，最後四捨五入
- 空白 → 顯示 `-`
- 非數字內容（停售、時價…）→ 原樣顯示，不參與運算

## 搜尋比對邏輯

移植自 `tcm-stock` 的 `tcm_lookup-20260825.html`（V2 搜尋核心），同一套評分分層：

| 層級 | 分數 | 說明 |
| --- | --- | --- |
| 完全相同 | 10000 | 正規化後字串相等 |
| 開頭符合 | 9000 + 查詢字數×10 | 品名以查詢字開頭（`桂枝` → `桂枝湯`） |
| 名稱包含 | 8000 + 查詢字數×10 | 查詢字出現在品名中間 |
| 含於品名 | 7600 + 品名字數×10 | 查詢字比品名長，且包含整個品名 |
| 編輯距離 | 5000 + 相似度×1000 | 相似度 ≥ 0.78（僅 3 字以上查詢） |
| 字元集合 | 4000 + 相似度×1000 | 共同字元 ≥ 0.75（僅 3 字以上查詢） |

- **輸入正規化**：簡體轉繁體（含 `锭→錠`）、全形英數轉半形、全形空白、`×＊∗→x`、
  去除 `?？、，,。．.·•` 等殘留標點、移除所有空白。
- **短查詢保護**：2 字以內只允許精確層，不做模糊比對，避免單字亂配。
- **多候選不自動猜**：短查詢命中多筆時全部列出並提示補字，不挑單一答案。
- **輸入即預選**：打字時輸入框下方跳出候選清單（品名＋分類＋符合度，最多 8 筆），
  可用滑鼠點選或鍵盤 ↑↓ 移動、Enter 選取、Esc 收起；選取後輸入框填入完整品名並重新整理表格。
- **低信心提示**：最佳分數未達精確層（< 8000）時標示「查無精確符合，以下為相似品項」。
- **符合度標籤**：每列品名後標示「完全符合／開頭符合／名稱包含／含於品名／相似」等。

### 與原始頁面不同的三處（為配合本頁資料形態）

1. **規格併在品名同欄**：原始頁面的品名與規格（200g／100g）分開儲存。本頁把
   `六味地黃丸 200g` 拆成核心 `六味地黃丸` 與規格 `200g`，兩者都參與評分取高者，
   因此輸入 `六味地黃丸` 也能精確命中。
2. **不因「完全相同」提早 return**：原始資料每個品名只有一筆；本表同一品名可能有多種
   規格（200g／丸劑 500g），提早 return 會把其他規格整列藏掉，故改為精確層全收、靠評分排序。
3. **未移植 `TYPO_MAP` 與 `AMBIGUOUS_TERMS`**：那兩張表是依庫存系統實際品項手工維護
   （例如 `柴胡湯 → 小柴胡湯／大柴胡湯`），本頁品項來自牌價表、清單不同。
   目前錯字與一音多藥是靠評分層與「多筆全列」的行為處理。

## 已驗證項目

以 `node verify.js` 實跑頁面內邏輯，**69 項全數通過**，涵蓋：

- CSV 解析（含引號內逗號、CRLF、BOM、表頭上方有標題列）
- 欄位對應與缺欄偵測、非數字值保留
- 品名／規格拆分（`桂枝湯 200g`、`六味地黃丸 丸劑 500g`、`科學中藥錠劑 1000錠`、無規格品名）
- 正規化（簡繁、全形數字、空白、標點）與 Levenshtein／字元集合相似度
- 評分分層數值（10000／9030／8020）與符合度標籤
- 搜尋行為：簡體查詢命中、單方與方劑同時列出、同品名多規格都保留、錯一字模糊命中、查無此藥
- 折扣／5+1／10+1 與疊加計算
- 表格渲染（千分位、`-` 空白、文字值、符合度標籤）、提示訊息、分類篩選
- 輸入預選清單（候選數量、排序、空查詢不顯示、上限、HTML 轉義）

另以瀏覽器實測（`http://localhost:8123`）：`桂枝汤`（簡體）命中、`炙甘草` 同時列出單方與
方劑並標示符合度、`地黃` 顯示多筆提示、`六味地黃凡` 以模糊比對命中並提示確認。

## 尚未驗證（重要）

- **Google 試算表的實際內容無法驗證**：本機與雲端環境都連不到 `docs.google.com`
  （連線逾時或 400），因此無法確認該試算表是否已公開、表頭是否與上表一致、資料筆數為何。
  若狀態列出現「試算表缺少欄位」，代表欄名與預期不符，請對照上表修正欄名。
- 藥廠牌價的正確性屬業務判斷，程式只負責顯示與換算，未做價格合理性檢查。
- 真實牌價資料下的比對效果尚未實測：目前只用 7 筆示範資料驗證；資料量放大到數千筆時，
  1～2 字短查詢會頻繁命中多筆並跳出提示，實際體感需要你的資料才判斷得準。
